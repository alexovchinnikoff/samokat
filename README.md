**Стек:** Python, Pytest, Postman, DevTools, Android Studio, PostgreSQL.

---

## 🎯 Что тестировал
1. **Веб (заказ):** UI, валидация полей, API.
2. **Мобильное (курьер):** ретест и регрессия.
3. **База данных:** проверка статусов заказов и целостности данных.
4. **Автотесты:** сценарий «Создать заказ → Получить по треку».

---

## 💻 Веб-тестирование: цифры и риски

*   **Окружения:** 4 конфигурации (Chrome/Яндекс Браузер, разные разрешения).
*   **Всего проверок:** 1465.
*   **Успешно:** 675 (46%).
*   **Найдено багов:** 40 (1 блокирующий, 25 критических).

### 🔥 Главные риски (почему нельзя релизить)
*   **Блокирующий баг в Chrome:** нельзя сделать заказ в самом популярном браузере.
*   **Валидация номера телефона:** система пропускает неверный номер. Заказ уходит курьеру, но связаться с клиентом нельзя → срыв доставки. Это опаснее ошибки в адресе.
*   **«Серая зона» ТЗ:** непонятно, кто должен проверять поля формы («Про аренду») — фронтенд или бэкенд.

## 📱 Мобильное приложение

*   **Ретест:** проверено исправление багов. Исправлено: 3, не исправлено: 1, новых найдено: 4.

## 🗄️ Работа с базой данных (PostgreSQL)

*   **Задача:** проверить, что статусы заказов в БД соответствуют логике приложения.

*   **Результат:** написал SQL-запросы для проверки статусов и количества заказов курьеров. Подтвердил корректность логики отображения статусов.
